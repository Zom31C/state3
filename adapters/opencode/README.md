# Адаптер state3 для opencode

Даёт opencode тот же внешний слой состояния Σ, что и расширение для Qwen Code:
задача разработки хранится в `.state3/state.db` проекта (там же — база знаний
проекта: страницы, связи и полнотекстовый поиск), патчи валидируются
MCP-сервером, а компактная Σ попадает в контекст модели — поэтому прогресс
переживает сжатие сессии и перезапуск.

Проверено для **opencode 1.18.26** (Windows). Источники фактов — пакет
`@opencode-ai/plugin@1.18.26`
(`C:\Users\<user>\.config\opencode\node_modules\@opencode-ai\plugin\dist\index.d.ts`)
и официальная документация `opencode.ai/docs/plugins`, `opencode.ai/docs/mcp-servers`.

## Состав

| Файл                    | Назначение                                                                                                                                                                                   |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `plugin/state3.js`      | плагин: инжекция Σ в системный промпт и в контекст сжатия, опциональный guard опасных действий, режим `--self-test`                                                                          |
| `opencode.example.json` | пример блока `mcp` для подключения сервера state3                                                                                                                                            |
| `AGENTS.md`             | дополнение к общим правилам из [`templates/AGENTS.md`](../../templates/AGENTS.md): только то, что в opencode устроено иначе (префиксы инструментов, инжекция плагином, `STATE3_HOME`, guard) |

## Установка

```bash
# 1. Собрать сервер в репозитории state3
cd D:\Projects\skillState
npm install && npm run build

# 2. Плагин — в каталог плагинов проекта (или глобально: ~/.config/opencode/plugins/)
mkdir .opencode\plugins
copy adapters\opencode\plugin\state3.js .opencode\plugins\state3.js

# 3. MCP-сервер — в конфигурацию проекта: скопировать блок mcp из примера
#    в opencode.json (или opencode.jsonc) и поправить пути на свои
copy adapters\opencode\opencode.example.json opencode.json

# 4. Правила — в AGENTS.md проекта: общий шаблон + дополнение opencode
copy templates\AGENTS.md <проект>\AGENTS.md
#    затем дописать к нему секцию «opencode specifics» из adapters\opencode\AGENTS.md
#    и заполнить секцию «## This project» в конце

# 5. Проверка
opencode mcp list
node .opencode\plugins\state3.js --self-test D:\Projects\skillState
```

Каталоги плагинов, которые opencode загружает автоматически: `.opencode/plugins/`
(проект) и `~/.config/opencode/plugins/` (глобально); принимаются `.js` и `.ts`.
Плагин — именованный экспорт асинхронной функции (`export const State3 = async ({ project, client, $, directory, worktree }) => hooks`);
объекты `output` в хуках мутируются на месте.

## Что делает плагин

| Хук                                  | Действие                                                                                                                                                              | Статус факта                                       |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `experimental.session.compacting`    | `output.context.push(Σ)` — состояние попадает в промпт сжатия, поэтому прогресс не теряется при компакции; туда же идёт бриф базы знаний                              | документировано (docs/plugins)                     |
| `experimental.chat.system.transform` | `output.system.push(Σ)` — компактная Σ в системном промпте каждого запроса (аналог UserPromptSubmit-хука Qwen Code); бриф добавляется только на первом запросе сессии | есть в типах 1.18.26, в документации не описан     |
| `tool.execute.before` (opt-in)       | `throw` блокирует вызов `bash`/`write`/`edit`/`patch`, если `next.risk` активной задачи `destructive` или `external`                                                  | документировано (throw отменяет вызов инструмента) |

Переменные окружения:

| Переменная         | По умолчанию               | Назначение                                                                                                                                                                                       |
| ------------------ | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `STATE3_ROOT`      | каталог проекта (см. ниже) | где искать `.state3/`                                                                                                                                                                            |
| `STATE3_STATE_DIR` | не задана                  | абсолютный путь каталога состояния; приоритетнее `STATE3_ROOT` и эвристики — для запуска opencode вне каталога проекта                                                                           |
| `STATE3_HOME`      | не задана                  | каталог репозитория state3 со сборкой: нужен корню с `state.db` (оттуда импортируется `dist/tasks/inject.js`). Без него плагин читает только легаси-JSON, а для корня с базой пишет в лог `warn` |
| `STATE3_NO_SYSTEM` | не задана                  | `1` — не инжектировать Σ в системный промпт (оставить только сжатие)                                                                                                                             |
| `STATE3_GUARD`     | не задана                  | `1` — включить блокировку опасных вызовов инструментов                                                                                                                                           |

Каталог проекта плагин определяет сам: сначала явный `STATE3_ROOT`, затем
первый подходящий из `directory`, `worktree`, `project.worktree`,
`process.cwd()`, где «подходящий» — абсолютный путь, не являющийся корнем
файловой системы. Если подходящих несколько, выигрывает тот, где уже лежит
`.state3/`. Проверка на корень нужна потому, что opencode 1.18.26 передаёт
`worktree: "/"` для проекта без git-репозитория (`project.id === "global"`), а
Bun считает `"/"` абсолютным путём — без неё состояние искалось в
`\.state3`. Выбранный каталог плагин логирует при загрузке
(`loaded (state: ...)`, видно с `--print-logs`).

Guard по умолчанию выключен: он намеренно прерывает вызов инструмента, и включать
его стоит там, где подтверждение опасных действий нужно enforce, а не только
рекомендовать. Второй уровень защиты — штатная система разрешений opencode
(диалоги подтверждения, `permission.ask`).

### Как плагин читает состояние

Корень с `state.db` плагин читает **через сборку state3**. С 12.09.2026 состояние живёт в
одном файле SQLite (`.state3/state.db`, раздел 12
[INTEGRATION.md](../../INTEGRATION.md)), а чтение SQLite требует драйвера: плагин находит
репозиторий (`STATE3_HOME` → обход каталогов вверх от самого файла, маркер
`dist/tasks/inject.js`) и зовёт оттуда `readInjection` — тот же маршрут, что и у хука Qwen
Code. Автономность файла стала частичной: копия в `.opencode/plugins/` без `STATE3_HOME`
сборку не находит и для мигрированного корня пишет в лог предупреждение (`level: warn`) вместо
Σ — молча ничего не пропадает. Легаси-корень без `state.db` читается прежним встроенным
способом и сборки не требует. Корень со `state.db` авторитетен: JSON-файлы рядом с ним — архив,
который оставила миграция, и плагин их не инжектирует.

До 12.09.2026 плагин перебирал только `*.json`, поэтому в мигрированном проекте Σ молча
исчезала из контекста, а opt-in guard терял `next.risk` и переставал блокировать опасные
вызовы. Исправлено в тот же день; проверка — в `smoke:mcp` (плагин запускается на настоящей
базе и печатает Σ вместе с брифом).

Плагин вводит и бриф базы знаний (`## Project brief (state3)`) — на первом запросе сессии и
при сжатии, но не на каждом запросе: карта стоит своих токенов один раз, а при сжатии её стоит
унести в саммаризацию. Ключ сессии — `sessionID` из аргумента хука; если хост его не передал,
бриф вводится один раз на процесс.

Запись задачи несёт поля `skill` (навык, которому принадлежит Σ) и
`notation` (`plain` | `compact`). **Легаси-путь их игнорирует**: из JSON-записи
плагин берёт только `id`, `updatedAt`, `state.status`, `state.next.risk` и сам
`state`, поэтому заголовок выглядит как `Task <id> (<status>):` — без имени
навыка и без напоминания о компактной нотации. Корень с `state.db` получает Σ в
том виде, в каком её рендерит сборка (`renderTaskHead` в `src/tasks/render.ts`),
то есть с навыком и напоминанием: `Task <id> [dev-task] (active):`.
`STATE3_PROJECTS` плагин не читает ни там, ни там: инжектируется один
корень — выбранный эвристикой либо заданный `STATE3_ROOT`/`STATE3_STATE_DIR`.

Инструментов это не касается: opencode подключает тот же сервер state3 (в
`opencode.example.json` — через лаунчер расширения `bin/state3-mcp.mjs`,
который импортирует `dist/mcp/server.js`), поэтому агенту как
`state3_task_*` доступны навыки (`dev-task`, `supervise-task`), аргументы
`skill`/`notation`/`project`, path-ключи патчей (`{"plan[1].status":"done"}`) и
строки возможностей `skills:`/`projects:` в ответе `task_list`. Процедуру P
навыка и блок компактной нотации возвращает `task_show`. `STATE3_PROJECTS`
сервер берёт из своего окружения — окружения процесса opencode либо блока
`environment` его mcp-конфигурации (опция описана в docs/mcp-servers).

## Безопасность

- Плагин и сервер не исполняют shell/HTTP и не правят код: читаются и пишутся
  только файлы `.state3/`.
- `next.risk` в Σ помечает следующее действие (`safe` / `destructive` /
  `external`); правила P требуют запросить подтверждение пользователя до
  исполнения destructive/external.
- Любая ошибка чтения состояния приводит к «ничего не инжектировать», а не к
  падению сессии.

## Проверка и отладка

```bash
opencode mcp list                                       # сервер state3 и его статус
# --self-test печатает оба блока (Σ и бриф); корню с state.db нужна видимая сборка —
# STATE3_HOME или запуск из каталога репозитория
node adapters\opencode\plugin\state3.js --self-test D:\Projects\skillState
npm run smoke:mcp -- --server extensions\state3\bin\state3-mcp.mjs   # 31 проверка сервера
```

- Инструменты MCP регистрируются с префиксом имени сервера (в конфигурации
  отключаются маской `"state3_*": false`), то есть в сессии это
  `state3_task_show`, `state3_task_patch` и т. д.
- Для логов плагин использует `client.app.log({ body: { service: 'state3', level, message } })`
  (уровни `debug`/`info`/`warn`/`error`) — `console.log` в плагинах не
  рекомендуется. Строка `loaded (state: …, build: …, …)` при старте называет
  каталог состояния и найденную сборку (`none — legacy JSON only`, если её нет),
  а `warn` с упоминанием `state.db` означает, что база есть, но прочитать её
  нечем: Σ в контекст не попадёт, пока не задан `STATE3_HOME`.
- Значения в конфигурации поддерживают подстановку `{env:VAR}`; подстановки пути
  к проекту нет, поэтому в `opencode.example.json` стоят явные абсолютные пути —
  замените их на свои. Аргумент `--root` можно не указывать: тогда сервер возьмёт
  `<cwd>/.state3`.
- `timeout` у local MCP-сервера по умолчанию 5000 мс; в примере выставлено 10000
  на первый холодный старт node.

### Сквозная проверка на локальной модели (без ключей API)

Локальная Ollama закрывает E2E без внешних провайдеров: провайдер объявляется в
`opencode.json`, после чего модель появляется в `opencode models` как
`ollama/<имя>`:

```json
{
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": { "baseURL": "http://localhost:11434/v1" },
      "models": { "qwen3.8:27b": {} }
    }
  }
}
```

```bash
opencode run -m ollama/qwen3.8:27b --print-logs --log-level INFO "позови state3_task_list и назови goal активной задачи"
```

Признаки успешного прогона в логе: `loaded (state: <проект>\.state3, ...)`,
`evaluated permission=state3_task_list ... action=allow`, строка вызова
инструмента и ответ модели, цитирующий `goal` из инжектированной Σ.

## Ограничения

- `experimental.chat.system.transform` и `permission.ask` присутствуют в типах
  плагина 1.18.26, но не описаны в публичной документации: если в будущей версии
  opencode их уберут, плагин продолжит работать через
  `experimental.session.compacting` (инжекция в системный промпт просто
  перестанет происходить, ошибка логируется в debug).
- Прямой «инжекции в каждый пользовательский промпт» в opencode нет — Σ
  добавляется в системный промпт и в контекст сжатия; в остальном агент читает
  состояние инструментом `task_show`.
- Плагин не знает о навыках, нотации и чужих проектах (см. «Что плагин не
  читает»): в инжектируемом блоке нет имени навыка и напоминания о компактной
  нотации, а добавляется Σ только одного корня. Агент добирает остальное через
  `task_show` (процедура P и блок нотации) и `task_list` (навыки и проекты).
